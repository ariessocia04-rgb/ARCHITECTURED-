# 1PLAN EXTENSION — CODEX CODE CONTROL CENTER

## Authority

`1plan.md` remains the master source of truth. This additive extension records the owner-approved creation of `Codex Code/` as the canonical Codex task-control and evidence area.

## Purpose

The control center prevents destructive or duplicated implementation by requiring every Codex task to preserve canonical source placement while storing its prompt, authorization, task record, changed-file manifest, tests, security review, reviewer result, and merge evidence in one traceable task folder.

## Canonical target

```text
Codex Code/
```

## Placement rule

Actual application code remains in approved canonical implementation paths:

```text
apps/
packages/
supabase/
tests/
infrastructure/
docs/
```

`Codex Code/` must not become a second source-code tree. It stores references and evidence for canonical code changes.

## Required task relationship

```text
Approved architecture and Release plan
→ Codex Code armored prompt
→ Codex Code task contract/record
→ isolated branch
→ canonical implementation paths
→ tests and evidence
→ draft PR
→ external review
→ merge/read-back record
→ STOP
```

## Non-negotiable rules

- No deletion, rename, move, or replacement without exact authorization.
- Search and classify existing work before creating anything.
- Reuse and extend canonical implementation; do not create parallel versions.
- One task ID uses one task folder.
- Codex cannot approve or merge its own work.
- Next task remains unauthorized until separately approved.
- No secrets or real customer/payment/device-sensitive data in task evidence.
- No complete source-code copies under `Codex Code/`.
